凭据在云途后台「用户设置 → API设置」获取。当前使用的是 **OMS 模式（客户代码 + API 密钥，Basic Auth）**，不是新版 OpenAPI（AppId/AppSecret）。

### 调试用速查

Basic Auth 头的生成方式：`Base64("客户代码&API密钥")`（注意中间是 `&`）：

```
Authorization: Basic Q041ODM0Jm9IUmwyOHdPbVFvPQ==
```

直接 curl 测试面单接口：

```bash
curl -X POST http://oms.api.yunexpress.com/api/Label/Print \
  -H "Authorization: Basic Q041ODM0Jm9IUmwyOHdPbVFvPQ==" \
  -H "Content-Type: application/json;charset=UTF-8" \
  -d '["YT2501234567890"]'
```

返回 `Code: "0000"` 且 `Item[0].Url` 有值即为正常，`Url` 就是面单 PDF 下载地址。

## 2. 核心客户端：`src/lib/yuntuClient.ts`（双模式）

系统支持两种云途接口模式，由环境变量 `YUNTU_API_MODE` 切换，**当前生产用的是 OMS 模式**。

### 模式一：OMS API（当前生效）

- **地址**：`http://oms.api.yunexpress.com`
- **接口**：`POST /api/Label/Print`，请求体就是运单号数组（如 `["YT...","YT..."]`）
- **鉴权**：`Authorization: Basic Base64("客户代码&API密钥")`
- **响应**：`Code === "0000"` 为成功，面单地址在 `Item[].Url`，`Item[].OrderInfos[].CustomerOrderNumber` 标识单号归属

**批量逻辑（`getYuntuLabelsOms`，这是关键设计）：**

1. 按 20 单一批 POST 单号数组（云途批量接口只返回"已生成面单"的订单，数量可能少于请求）；
2. 按 `CustomerOrderNumber` 精确匹配拿回面单；
3. 批量响应里**没拿到面单的单号，逐个单独调用兜底**，保证每个单号都有准确的成功/失败结果和错误原因。

单张失败不阻塞整批。

### 模式二：OpenAPI（新版，当前未启用）

- **地址**：`https://openapi.yunexpress.cn`
- **鉴权**：OAuth2 `client_credentials` 换 accessToken（缓存 50 分钟，有效期约 1 小时）+ 每请求 HMAC-SHA256 签名
- **接口**：`GET /v1/order/label/get?order_number={运单号}`（单次仅支持 1 个单号，系统用 4 路并发逐单调用）
- 签名串：`body=&date={date}&method=GET&uri={uri含查询串}`，sign = Base64(HMAC-SHA256(AppSecret, 签名串))

### 对外入口

| 函数 | 用途 |
| --- | --- |
| `getYuntuLabel(orderNumber)` | 单号直查（调试接口用） |
| `getYuntuLabels(orderNumbers)` | 批量取面单：OMS 走批量+兜底；OpenAPI 走 4 路并发 |
| `isYuntuConfigured()` | 判断 `YUNTU_APP_ID`/`YUNTU_APP_SECRET` 是否已配置，决定降级策略 |

## 3. 服务端 API 路由

### 3.1 `POST /api/wms/labels/pdf` —— 批量面单 PDF（**主链路，所有打印入口都走它**）

流程：

```
前端勾选订单 → POST {ids:[...]}（最多100单）
  → requireStaffSession() 鉴权（需员工登录）
  → getOrdersByIds(ids) 查订单
  → 云途已配置？
      否 → 直接返回 400「云途 API 未配置」（此接口无降级）
      是 → 取有运单号(trackingNo)的订单 → getYuntuLabels() 批量调云途
  → 逐单下载面单文件（20秒超时，单张上限5MB）
  → pdf-lib 合并为单个 PDF：
      · 仅取每个源 PDF 的第一页（云途 PDF 可能含面单+回执/报关单，只打面单）
      · 保留云途原始 10×10cm 页面尺寸（283.46pt，实测283.92pt），不缩放不重绘，避免条码失真
      · 尺寸偏差>4pt 只记警告不处理
  → 返回 application/pdf，统计放响应头：
      X-Label-Total  请求单数
      X-Label-OK     成功合并数
      X-Label-Failed encodeURIComponent(JSON) 的失败明细 [{parcelNo, error}]
```

失败情况：全部失败返回 422 + failed 明细；部分失败照常返回 PDF，失败单跳过。

### 3.2 `POST /api/wms/labels/batch` —— 批量取面单元数据（返回 URL，不合并 PDF）

与 pdf 路由同样先调云途，但只返回每单的面单 `url`/`labelType`。区别在于**有降级**：云途未配置时返回 `type: "internal"`（系统内部面单）。每个订单返回四种类型之一：

| type | 含义 |
| --- | --- |
| `yuntu` | 云途面单获取成功，附 url + labelType(PDF/PNG/ZPL) |
| `yuntu-error` | 云途调用失败，附 error 原因 |
| `no-tracking` | 订单无运单号（提示先在云途获取运单号） |
| `internal` | 云途未配置，降级内部面单 |

`GET /api/wms/labels/pdf?orderNumber=YT...` 和 `GET /api/wms/labels/batch?orderNumber=...` 是单号直查调试接口。

### 3.3 `POST /api/wms/orders/mark-printed` —— 标记已打印

打印**成功之后**才调用（用户在弹窗确认，或扫码枪流程确认打印完成）。请求体：

```json
{ "ids": ["..."], "labelInfo": { "<orderId>": { "url": "...", "labelType": "PDF" } } }
```

`labelInfo` 会把云途面单 URL 缓存进订单表（`label_url` 列），**二次打印直接用缓存，不再调云途**。同时订单状态从 `imported` → `printed`（记录 `label_printed_at`）。

## 4. 三个打印入口（前端）

### 4.1 订单管理页（WmsConsole）——「批量打印」

```
勾选订单 → handleBulkPrint()
  → POST /api/wms/labels/pdf（当前页勾选的订单）
  → 拿到合并 PDF 的 blob → window.open 新窗口（浏览器 PDF 查看器直接打印）
  → 弹「打印确认条」：用户确认打印成功
  → POST /api/wms/orders/mark-printed 标记已打印
```

- 顺序 = 当前列表排序（勾选顺序即列表顺序），面单按此顺序合并成单个 PDF；
- 失败单跳过并在提示里显示第一个失败原因；
- 取消打印确认则不标记，订单保持 `imported`。

### 4.2 扫描打印页（scan-print）—— 扫码枪自动打印

```
扫码（包裹号/运单号）→ /api/wms/scan-print/match 匹配订单
  → POST /api/wms/labels/pdf（单张）
  → 静默打印（QZ Tray，走 silentPrint.ts）或打开 PDF
  → 打印成功才 mark-printed；失败保留任务供重试
  → 回到空闲态，继续扫下一单
```

静默打印依赖本机 QZ Tray（wss://localhost:8181），面单按 10×10cm 直接发给热敏打印机。

### 4.3 SKU 专属打包窗口（sku-view）—— 分组批量打印

`printLabels()` 同样复用 `/api/wms/labels/pdf`，超 100 单自动分批循环调用；打印确认条上「打印成功，标记已打印」只标记成功获取面单的单。

## 5. 整体链路图

```
[订单管理批量打印] ─┐
[扫描打印 自动打印] ─┼─→ POST /api/wms/labels/pdf ─→ yuntuClient.getYuntuLabels()
[SKU打包窗口 打印] ─┘         （需员工登录）              │
                                                        ├─ OMS模式(当前): POST oms.api.yunexpress.com
                                                        │    /api/Label/Print, Basic Auth
                                                        │    批量20单/批 + 失败单逐个兜底
                                                        │
                                                        └─ OpenAPI模式: token + HMAC签名
                                                             GET openapi.yunexpress.cn
                                                             /v1/order/label/get (4路并发)
        ↓ 云途返回面单 URL
   服务端下载 PDF → pdf-lib 合并（每单取第1页，保留10×10cm原始尺寸）
        ↓
   返回合并 PDF → 前端打印（新窗口 / QZ 静默打印）
        ↓ 用户确认打印成功
   POST /api/wms/orders/mark-printed
   → 状态 imported→printed，label_url 缓存面单地址（下次不再调云途）
```

## 6. 关键设计要点 & 排查指引

| 现象/问题 | 原因与排查 |
| --- | --- |
| 打印报「云途 API 未配置」 | 服务器 `.env.production` 缺 `YUNTU_APP_ID/SECRET`，或 PM2 未加载该 env（重启 `pm2 restart ows`） |
| 报「无运单号，请先在云途获取运单号」 | 订单 `tracking_no` 为空（导入 Excel 时未带 YT 运单号），走 `no-tracking` 分支 |
| 报「云途未生成面单」 | 云途侧该运单尚未出单或状态异常（OMS 响应 `OrderInfos[].Code != 100`），等云途出单后重试 |
| 部分单被跳过 | 正常设计：批量接口漏掉的单会逐个兜底重试，仍失败的进 `X-Label-Failed`，不阻塞其他单 |
| 二次打印很快 | `label_url` 已缓存，mark-printed 时写入订单表，跳过云途调用 |
| 面单条码打印模糊 | 合并时从不缩放，保留原始尺寸；若模糊检查打印机 DPI 与纸张（应为 10×10cm 热敏纸） |
| 想换新版 OpenAPI | `.env.production` 改 `YUNTU_API_MODE=openapi` 并换成 AppId/AppSecret，重启 PM2 即可，代码已内置双模式 |
| 密钥泄露/更换 | 云途后台重置 API 密钥 → 更新 `.env.production` → `pm2 restart ows`（token 缓存也会随重启清空） |

### 安全边界

- 所有 labels 路由均要求 `requireStaffSession()`（员工登录态），未登录返回 401；
- 密钥只存在于服务端环境变量，浏览器端拿不到（前端只见最终 PDF/URL）；
- 单批上限 100 单、单文件 5MB、下载超时 20s，防止拖垮服务。
