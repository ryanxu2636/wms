## 1. 目标与范围

### 1.1 目标
在 S1 导入引擎产出结构化订单（`package` / `package_item`）后，打通「库存 → 库位 → 订单分配 → 拣货 → 复核 → 打包 → 出库」的完整履约闭环，做到：

- **库存实时准确**：`stock` 以 `sku + location + batch` 三维度记账，每次变动全程留痕（`stock_transaction`）。
- **库位可上架可推荐**：支持一品多库位，上架时按「货架→列→层」路径推荐目标库位。
- **订单状态机可控**：待分配 → 已分配 → 拣货中 → 已复核 → 已打包 → 已出库，并含异常态（拦截 / 待人工复核 / 缺货挂起）。
- **分配不超卖**：可用库存锁定，组合 SKU 按 BOM 展开到子件，缺货自动挂起。
- **出库强卡点**：未打印面单不允许出库；出库即扣减库存并留痕。

### 1.2 验收标准（任务既定）
> 完整走通「待分配 → 已打包」；出库后可用库存正确扣减且全程留痕。

### 1.3 子模块与数据字典表映射

| 子模块 | 内容 | 涉及表（数据字典权威口径） |
|---|---|---|
| T2.1 实时库存 | 三维度库存 + 流水 | `stock`、`stock_transaction` |
| T2.2 库位管理 | 上架推荐、一品多库位 | `shelf`、`location`、`putaway_task` |
| T2.3 订单状态机 | 主流程 + 异常态 | `package` |
| T2.4 库存分配 | 锁定、BOM 展开、缺货挂起 | `allocation`、`bom`、`stock`、`package_item` |
| T2.5 拣货/复核/打包 | 路径排序、同 SKU 汇总 | `picking_task`、`packing` |
| T2.6 出库 | 扣减 + 流水 + 打印卡点 | `outbound`、`stock`、`stock_transaction` |

## 2. 数据模型（与数据字典对齐）

> 所有业务表统一包含标准审计字段：`id`（BIGINT UNSIGNED 自增 PK）、`created_at`、`updated_at`、`created_by`、`updated_by`、`deleted`（TINYINT 软删，默认 0）。下文不再逐表重复。

### 2.1 stock（库存台账）—— 核心不变式

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| sku_id | BIGINT UNSIGNED | UK 之一 | 商品 |
| location_id | BIGINT UNSIGNED | UK 之一 | 库位（快进快出未上架时可为暂存区库位） |
| batch_no | VARCHAR(64) | UK 之一，可空 | 批次号（batch_enabled=1 时必填） |
| production_date | DATE | — | 生产日期 |
| expiry_date | DATE | — | 有效期 |
| available_qty | INT | 默认 0 | 可用数量 |
| allocated_qty | INT | 默认 0 | 已分配（锁定）数量 |
| locked_qty | INT | 默认 0 | 锁定/质检数量 |
| in_transit_qty | INT | 默认 0 | 在途数量 |

- **唯一键** `UK(sku_id, location_id, batch_no)`。
- **不变式**：`总库存 = in_transit_qty + available_qty + allocated_qty + locked_qty`。
- **所有数量字段必须 `>= 0`**，由 DB `CHECK` 约束兜底。

### 2.2 stock_transaction（库存流水）—— 留痕不可变

| 字段 | 类型 | 说明 |
|---|---|---|
| stock_id | BIGINT UNSIGNED | 库存记录 |
| sku_id | BIGINT UNSIGNED | 商品（冗余，便于按 SKU 检索） |
| change_type | VARCHAR(32) | `inbound`/`outbound`/`allocate`/`release`/`adjust`/`transfer` |
| change_qty | INT | 变动数量（正负） |
| before_qty | INT | 变动前数量 |
| after_qty | INT | 变动后数量 |
| ref_type | VARCHAR(32) | `PO`/`RECEIVING`/`OUTBOUND`/`STOCKTAKE` 等 |
| ref_id | BIGINT UNSIGNED | 关联单据 id |
| remark | VARCHAR(255) | 备注 |

> **约束**：流水表只增不删不改（无 `updated_at` 语义，`deleted` 恒为 0）。每次库存变动必须在同一事务内写一条流水。

### 2.3 allocation（库存分配 / 锁定）

| 字段 | 类型 | 说明 |
|---|---|---|
| package_item_id | BIGINT UNSIGNED | 包裹明细 |
| sku_id | BIGINT UNSIGNED | 商品 |
| stock_id | BIGINT UNSIGNED | 库存记录（锁定来源） |
| alloc_qty | INT | 分配数量 |
| status | VARCHAR(16) | `allocated` / `released` |

### 2.4 其他复用表（口径以数据字典为准）

- `location`：`code` 三段式 `货架-列-层`（如 `A07-03-04`），`status` ∈ `empty/occupied/full/locked`，`shelf_id` 关联货架。
- `shelf`：`code` 货架编码（如 `A07`）。
- `putaway_task`：`from_location_id`（暂存区）→ `to_location_id`（推荐落点）。
- `bom`：`combo_sku_id` + `component_sku_id` + `qty`，`UK(combo_sku_id, component_sku_id)`。
- `package`：`status` 状态机（见 §4），含 `sla_deadline`、`is_resend`。
- `package_item`：`is_virtual`（YUN）、`is_marker`、`picked_qty`，`UK(package_id, sku_id)`。
- `picking_task`：`task_no`、`package_id`（按单拣）或空（波次拣）、`assignee_id`。
- `packing`：`status` ∈ `pending/checked/packed`。
- `outbound`：`label_printed`（TINYINT，未打印不允许出库）。

## 3. T2.1 实时库存

### 3.1 设计要点

1. **记账维度**：`stock` 唯一键为 `(sku_id, location_id, batch_no)`，任何入库/分配/出库都必须落到确定的一条 stock 行。
2. **流水强制**：封装统一的 `StockService`，对外只暴露事务方法（`allocate` / `release` / `outbound` / `adjust` / `transfer` / `inbound`），禁止直接 `UPDATE stock`。
3. **一致性保证**：
   - 分配/释放/出库均使用 `SELECT ... FOR UPDATE` 行锁，或乐观锁 `UPDATE ... WHERE available_qty >= ?` 判断影响行数。
   - 建议采用「乐观扣减 + 唯一键 upsert」：`UPDATE stock SET available_qty = available_qty - :n, allocated_qty = allocated_qty + :n WHERE id = :id AND available_qty >= :n`；影响行数为 0 则回滚提示库存不足。
4. **Redis 用途**：仅做库存「缺货快速判断」的缓存与失效，不替代 DB 记账（DB 是唯一事实源）。

### 3.2 核心方法

| 方法 | 触发 | 数量变动 |
|---|---|---|
| `inbound` | 入库/上架完成 | `in_transit_qty↓` 或 `available_qty↑` |
| `allocate` | 订单分配（T2.4） | `available_qty↓`，`allocated_qty↑` |
| `release` | 取消/拦截/复核驳回 | `allocated_qty↓`，`available_qty↑` |
| `outbound` | 出库（T2.6） | `allocated_qty↓`（不二次扣 available） |
| `adjust` | 盘点差异 | 对应字段增减，强制授权 + 备注 |
| `transfer` | 库位调拨 | 两个 stock 行一减一增 |

> 出库扣减的是 `allocated_qty`（分配阶段已从 available 挪到 allocated），确保「分配→出库」全程数量守恒，不会二次扣减。

## 4. T2.3 订单状态机（先定义，T2.4~T2.6 引用）

### 4.1 状态与迁移

```
                    ┌─────────────┐
    S1 导入 ──────▶ │ unassigned  │ 待分配
                    └──────┬──────┘
                           │ 分配成功(T2.4)
                    ┌──────▼──────┐
                    │  assigned   │ 已分配
                    └──────┬──────┘
                           │ 生成拣货任务(T2.5)
                    ┌──────▼──────┐
                    │   picking   │ 拣货中
                    └──────┬──────┘
                           │ 拣货完成
                    ┌──────▼──────┐
                    │   checked   │ 已复核
                    └──────┬──────┘
                           │ 打包完成
                    ┌──────▼──────┐
                    │   packed    │ 已打包
                    └──────┬──────┘
                           │ 出库(T2.6，须已打印面单)
                    ┌──────▼──────┐
                    │  outbound   │ 已出库（终态）
                    └─────────────┘
```

### 4.2 异常态（可在 assigned / picking 阶段进入）

| 状态 | 进入条件 | 处理 |
|---|---|---|
| `intercepted` 拦截 | 订单含 `CS99-No!!!` 标记 SKU（不可发货警告） | 停止出库，进异常队列，人工判断 |
| `manual_review` 待人工复核 | 订单含 `CS00-Check!!!` 标记 SKU；或明细「2 SKU 但总数 4/6」等歧义 | 强制人工复核后再放行 |
| `shortage_hold` 缺货挂起 | 分配时可用库存不足（含组合 SKU 子件不足） | 挂起等待补货，补货后重跑分配 |

### 4.3 状态机实现

- 定义 `ALLOWED_TRANSITIONS` 字典 + `PackageStateMachine` 校验类，非法迁移直接抛 `IllegalTransition`（HTTP 409）。
- 状态变更统一走 `transition(package_id, target, operator)`，写 `package.status` 并落操作日志。
- 枚举值严格对齐数据字典：`unassigned/assigned/picking/checked/packed/outbound/intercepted/manual_review/shortage_hold`。

## 5. T2.4 库存分配（核心算法）

### 5.1 分配入口
- 输入：`package_id`（单个）或批量（波次）。S2 阶段先实现**按单分配**，波次留待后续。
- 目标：为 `package_item` 中每条「非虚拟、非标记」明细，从 `stock` 锁定 `available_qty`，写入 `allocation`，并将 `package` 置为 `assigned`。

### 5.2 SKU 类型分流

| sku_type | 分配处理 |
|---|---|
| `base` | 直接按 `available_qty` 锁定 |
| `combo` | 不设实物库存，**按 BOM 展开到子件**（见 5.3） |
| `virtual`（YUN） | 免拣货、免库存、免面单，**跳过分配** |
| `marker` | 期初已剔除，订单含 marker 走拦截/人工复核（见 4.2），不参与分配 |

### 5.3 BOM 展开（组合 SKU）

**关键陷阱（数据字典明确）**：BOM 列格式 `子SKU*数量;子SKU*数量;`，但部分 SKU 名内含 `*`，必须用「最后一个 `*`」切分数量：

```python
def parse_bom_segment(seg: str) -> tuple[str, int]:
    idx = seg.rfind('*')          # 最后一个星号，而非第一个
    comp = seg[:idx].strip()
    qty = int(seg[idx+1:].strip() or 1)
    return comp, qty
```

- 组合 SKU 虚拟库存：`virtual_available = min(子件 available_qty ÷ 子件用量)`。
- 分配组合 SKU 时，递归展开到 `bom` 叶子（`sku_type=base`），对每个子件按其 `用量 × 订单数量` 锁定库存，生成多条 `allocation`（`package_item_id` 指向组合明细，`sku_id` 指向子件，`stock_id` 指向子件库存）。
- 任一子件可用不足 → 整单（或该明细）进入 `shortage_hold`，已锁定的部分**全部回滚释放**（原子性）。

### 5.4 分配算法（事务内）

```
BEGIN;
  FOR each package_item (非虚拟/非标记):
    need_qty = item.qty - item.picked_qty
    IF sku_type = combo:
        components = expand_bom(sku)          # 递归展开
        FOR each (comp_sku, per_qty):
            lock(comp_sku, need_qty * per_qty)
    ELSE:
        lock(sku, need_qty)
  校验全部锁定成功 → 写 allocation + stock_transaction
  任一失败 → ROLLBACK，package → shortage_hold
COMMIT;
```

- **锁定规则**：优先锁 `batch_no` 为空或近效期先出的库存（FEFO/FIFO，`expiry_date ASC` / `production_date ASC`）。
- **锁定顺序**：按 `stock_id` 升序加锁，避免死锁。

## 6. T2.2 库位管理 + 上架推荐

### 6.1 库位编码
三段式 `货架-列-层`，如 `A07-03-04`。`location.code` 唯一，`shelf_no/column_no/layer_no` 冗余存储便于排序与显示。

### 6.2 上架推荐（`putaway_task.to_location_id`）

推荐优先级（同 SKU 优先复用，其次就近/空位）：

1. **已有该 SKU 的库位**且 `status ∈ {occupied, empty}`（一品多库位，优先补入既有位）→ 推荐之。
2. 否则按 **`shelf → column → layer` 升序**找第一个 `status = empty` 的库位。
3. 无空位 → 返回「暂存区」库位，标记需人工处理。

```
ORDER BY shelf.code, column_no, layer_no
WHERE status = 'empty'
LIMIT 1
```

- 库位状态联动：上架完成 `empty → occupied`；库位库存清零 `occupied → empty`；人工可 `locked`。

### 6.3 一品多库位
- 同一 SKU 可在多个 `location` 各有一条 `stock`（`batch_no` 不同或库位不同）。
- 拣货/出库时按路径排序取货，见 §7。

## 7. T2.5 拣货 / 复核 / 打包

### 7.1 拣货任务生成（`picking_task`）
- 订单 `assigned → picking` 时，按 `allocation` 汇总生成拣货任务。
- **同 SKU 汇总**：同一 SKU 跨多库位的分配，合并为一条拣货项，标注各库位数量。
- **路径排序**：拣货项按库位 `货架→列→层` 排序，减少走回头路。
- 生成 `picking_task`（`task_no` 规则：`PK + 日期 + 序号`），关联 `package_id`（按单拣）。

### 7.2 拣货完成 → 复核
- 拣货员确认拣货完成，`picking_task.status = done`，`package → checked`。
- 复核（`packing.status: pending → checked`）：核对实物与 `package_item` 数量一致；不一致则 `package → manual_review`。

### 7.3 打包
- 复核通过后打包，`packing.status → packed`，`package → packed`。
- 打包后触发面单打印（S3 的批量打印能力，S2 预留 `outbound.label_printed` 字段与接口桩）。

## 8. T2.6 出库

### 8.1 出库卡点
- **硬卡点**：`outbound.label_printed == 0` 时，出库接口返回 409，提示「面单未打印，禁止出库」。
- 出库前置校验：`package.status == packed`；`outbound.status == pending`。

### 8.2 出库执行（事务内）

```
BEGIN;
  SELECT package FOR UPDATE;               -- 校验 status = packed
  SELECT outbound FOR UPDATE;              -- 校验 label_printed = 1
  FOR each allocation (status=allocated):
      UPDATE stock SET allocated_qty -= alloc_qty   -- 扣减已分配
      INSERT stock_transaction(change_type='outbound', change_qty=-alloc_qty, ...)
  UPDATE outbound SET status='shipped', shipped_at=now()
  UPDATE package SET status='outbound'
COMMIT;
```

- 出库扣的是 `allocated_qty`，保证「分配→出库」守恒。
- 每个 `stock` 变动都写 `stock_transaction`（`before_qty` / `after_qty` 留痕）。

## 10. 关键风险与待确认项

| # | 风险 / 待确认 | 影响 | 建议 |
|---|---|---|---|
| 1 | **组合 SKU 子件不足时的挂起粒度**：整单挂起 vs 单明细挂起 | 分配原子性 | 建议整单原子回滚挂起（避免半分配），待确认 |
| 2 | **锁库存优先级**：FEFO（近效期先出）是否本阶段强制 | 批次库存 | 建议 `expiry_date ASC` 默认，可配置 |
| 3 | **波次拣货**（`picking_task.package_id` 为空）是否 S2 实现 | 范围 | 建议 S2 仅按单拣，波次留后续迭代 |
| 4 | **快进快出未上架库存**的库位兜底 | 分配 | 数据字典已明确「暂存区库位」，需确认暂存区库位 code |
| 5 | **并发下单分配**的性能与行锁范围 | 一致性 | 乐观锁 + 唯一键 upsert，压测验证 |
| 6 | 面单打印接口（S3）在 S2 的桩实现程度 | 出库卡点 | 先以 `label_printed` 字段 + 手动标记打通验收 |

## 11. 交付与验收

### 11.1 交付物
1. `stock` / `stock_transaction` / `allocation` 等表的 DDL 迁移脚本。
2. `StockService` / `AllocationService` / `PackageStateMachine` / `PickingService` / `OutboundService` 后端服务。
3. 上架推荐、订单分配、拣货、复核、打包、出库的 API 与前端页面（对齐《页面与流程清单》）。
4. 单元测试（状态机迁移、BOM 展开、库存扣减守恒）+ 集成测试。

### 11.2 验收用例（对齐任务标准）
1. 完整走通 `unassigned → assigned → picking → checked → packed → outbound`。
2. 出库后：`stock.allocated_qty` 正确扣减、`available_qty` 不变（已在分配阶段扣）、`stock_transaction` 全程留痕且 `before/after` 守恒。
3. 组合 SKU 订单按 BOM 正确展开到子件锁定，子件不足整单挂起。
4. 未打印面单出库被 409 拦截。
5. 含 `CS99/CS00` 标记 SKU 订单分别进入拦截/人工复核。
